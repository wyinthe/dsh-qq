# 排错

按症状查。表里的每一条都是实际踩过的。

## 消息发出去，QQ 没收到

| 先查 | 怎么查 | 常见原因 |
|---|---|---|
| 端口通不通 | `Test-NetConnection 127.0.0.1 -Port 3001` | WSL 停了 / NapCat 没起 |
| WSL 状态 | `wsl -l -v` 看是不是 `Running` | 关机、休眠、手动关过 |
| NapCat 有没有加载新配置 | 启动脚本返回 `10` = 已在跑 | **10 不会重载配置**，要先杀 `qq`/`xvfb-run`/`screen` |
| 白名单 | 日志有没有「忽略非白名单」 | `owners` 写错号，或写成字符串 |
| 会话 | `stateDir/state.json` 里的 `sessionId` | `resume` 失败时插件会丢消息（这是故意的） |

## 桌面说一句，手机也收到 / 手机说一句，桌面又出现一遍

- 前者说明分流没生效：确认插件是新版（日志里应有「这轮不是 QQ 发起的，不回推」）。
- 后者不是 bug：绑了同一间会话，QQ 的消息本来就会出现在那间里。

## 一发消息就报 503 / connect-refused

```
LlmError: 503 "acp-proxy failure: connect-refused 127.0.0.1:9931"
```

`agent-default-model` 指向了本地服务，而它没起。两种修法：

1. 在插件配置里固定 `provider` / `model`（推荐）；
2. 或者先把本地模型起起来（作者的 `启动本地模型.bat`）。

## 建会话直接抛错

```
TypeError: (intermediate value)?.commit is not a function
```

插件里给 `agents.create/resume` 传的 `setup` **不能 return agent**：引擎会把返回值当提交句柄调
`.commit()`。`setup` 里只做挂载，最后 `return undefined`。

## 语音来了，只有占位没内容

| 检查 | 说明 |
|---|---|
| 配了 `earScript` 吗 | 没配就是「没配 earScript，这条语音只留了占位」 |
| 脚本能单独跑吗 | `node <earScript> <某个 wav>` 看 stdout |
| 音频格式 | QQ 语音是 AMR，微信是 SILK，都要先转 wav 再喂 ASR |
| 输出格式 | 转写在普通行，语气必须以 `[语气]` 开头，否则会被当成转写的一部分 |

## 图片发不出去

```
failed retcode 1200 ENOENT ... /D:/xxx.png
```

NapCat 在 WSL 里，看不见 Windows 盘符。插件已经自动把本地文件读成 `base64://` 发；
如果你手写了 `file:///D:/...`，就会报这个。

## 重启后插件没加载

- 看日志有没有 `[dsh-qq] 已加载 …`；
- `package.json` 的 `dsh.profile.bundles` 里有没有 `dsh-qq`；
- 用 link 装的话，改完源码要重启（插件没有热重载）。
