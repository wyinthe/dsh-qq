# 用法与行为

## 一、收发标记

### 出站（AI → QQ）

写在回话文本里，发出去时会被解析并剥掉：

| 标记 | 结果 |
|---|---|
| `[[img:绝对路径]]` | 图片。插件读文件 → `base64://` 发；文件不存在会跳过并记日志 |
| `[[face:178]]` | QQ 内置表情（编号见 QQ 表情表） |
| `[[mface:emoji_id/package_id/名字]]` | 商城表情包 |

限制与细节：

- 图片必须本地可读；**不要写 WSL 路径**——NapCat 在 WSL 里，看不到 `D:\`。
- 同一句里可以混排：文字 + 图片 + 表情，按出现顺序拆成消息段。
- 纯文字超过 `maxChars`（默认 1800）会按段落切成多条。

### 入站（QQ → AI）

| 消息类型 | 变成 |
|---|---|
| text | 原文 |
| record（语音） | `[语音] <转写>` + `[语气] <声学层摘要>`（需配 `earScript`） |
| image | `[用户发了图片，已存到本机，可以直接用 read_image 打开：<路径>]` |
| face | `[QQ表情 id=178]` |
| mface | `[表情包「名字」emoji_id=… package_id=…]` |
| 其它 | `[收到<类型>消息]` |

图片落盘位置：`tmpDir`（默认 `<系统临时目录>/dsh-qq`），文件名 `qq-<时间戳>-<随机>.<扩展名>`。
下载有上限（12 MB）与超时（20 秒），超了记「没能下载下来」。

## 二、回话分流（重要）

插件记一个「本轮是否由 QQ 发起」的窗口：

- QQ 发消息进来 → 投递进会话 → **开窗**（30 分钟）；
- 会话产出一条回复 → 窗还开着 → 发到 QQ，**然后立刻关窗**；
- 桌面发起的轮次 → 窗是关的 → 只在桌面显示，日志打一句「这轮不是 QQ 发起的，不回推」。

意义：你在电脑前说话，手机不会震；你在手机上说，电脑那边也不会重复一条。
一次投递只回一次，不会因为 AI 连发几条就刷屏。

## 三、会话绑定

`sessionId` 有两种行为：

| 配置 | 行为 |
|---|---|
| 留空 | 第一次收到消息时自建一间（`session-<uuid>`），id 存 `stateDir/state.json`，之后复用 |
| 填了 | 一直用那一间；**resume 失败就丢弃这条消息，绝不新建**（否则会出现两个「我」） |

绑定同一间的好处：手机与桌面的上下文是连续的——你在 QQ 说的话，桌面上也看得见。

## 四、已知限制

1. **不发语音条**。发语音要 `ffmpeg` 转 24k 单声道 + `silk-wasm` 编码 + `record` 消息段；
   作者在自家环境里跑通过，但没有打进这个包（会引入两个外部依赖）。要的话照这三步接。
2. **不收群消息**。`groupMessages: false` 时群消息只打一行日志。开成 `true` 也只是「当输入」，
   没有 @ 识别、没有多人隔离——不建议直接开。
3. **只认白名单**。`owners` 之外的私聊直接忽略，连日志都只有一行。
4. **没有重连之外的容错**。WS 断了 5 秒重连；长时间断线期间的消息不会补发（NapCat 不重放）。
